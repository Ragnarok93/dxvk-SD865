# FFVII Remake / SD865: DXVK 3.1.1 8-bit storage failure — hardware vs wrapper

**Status (2026-10-11):** the user's FF7Remake DXVK 3.1.1 Wine/DXGI logs identify `storageBuffer8BitAccess` rejection on the Adreno 650. Mesa/Turnip *reference source* makes this more likely a **genuine A650 unsupported feature** than the initially suspected wrapper omission. **The precise T30 driver binary remains unqueried.** Do not force-enable 8-bit storage or advertise Vulkan 1.4 conformance based on a version string.

## Primary evidence

- User log: `Found device: Wrapper(PurpleVK-public Adreno (TM) 650 (git-62ac221a33)/unknown) (Wrapper driver 26.2.99)` followed by `Skipping: Device does not support required feature 'storageBuffer8BitAccess'`, `No adapters found`, and `Failed to initialize DXVK.` DXVK identified itself as 3.1.1. Game FEX ARM64EC loaded, but no actual gameplay rendering.
- Mesa reference source inspected at `leegao/mesa-wrapper-CI@417776cc61eb137f0f22f24292f528d396c7189a` (this is the **reference wrapper/Mesa source family**, not independently verified as the user's exact Turnip T30 binary):
  - `src/freedreno/common/freedreno_devices.py` around line 662: `GPUId(650)` uses `[a6xx_base, a6xx_gen3]`; neither definition sets `storage_8bit`.
  - `src/freedreno/vulkan/tu_device.cc` around lines 399,146: `storageBuffer8BitAccess = pdevice->info->a7xx.storage_8bit` and `VK_KHR_8bit_storage = device->info->a7xx.storage_8bit`.
  - `src/freedreno/common/freedreno_devices.py` around line 904: `storage_8bit=True` only in newer `a7xx_gen3` profile, not A650's A6xx gen3.
  - `src/vulkan/wrapper/vk_wrapper_features_gen.py`: `wrapper_setup_device_features` generated code **already calls the underlying ICD's `GetPhysicalDeviceFeatures2`** and imports the Vulkan 1.2 feature chain. Thus absence of this flag can originate directly from Turnip, not just an accidental wrapper omission.
- Newer mainline Mesa Turnip source also ties `storageBuffer8BitAccess` to `pdevice->info->props.storage_8bit`, rather than advertising it universally. The Vulkan 1.4 spec requires it, whereas Vulkan 1.3 permits it to be absent.
- External `jtiberius9-spec/vili-wrapper-build` unconditionally sets 8-bit bits in an Adreno 660 wrapper. That *may* unblock some apps, but this is **not sufficient evidence of underlying 8-bit storage correctness on A650** and must not be copied blindly.
- The Wine trace has `wine_vkCreateInstance API version 0x403000` (the *requested* Vulkan 1.3 instance version); this does NOT establish the underlying physical device API version. Wrapper driver `26.2.99` is not a Vulkan version.

## Engineering disposition

**Known working:** DXVK 2.7.1 is user-reported functional. Preserve exact WCP and focus compatible SD865 optimizations/backports on 2.7.1. This is the immediate path to game performance work.

**Experimental hardware audit:** `tools/ff7r_wrapper8bit_patch.py` and `.github/workflows/ff7r-wrapper8bit-verified.yml` build a separately identified wrapper that directly re-queries raw driver 8-bit storage + shaderInt8 bits, copies only the **raw reported** values into the wrapper's base feature table, and logs the result with `WRAPPER_FF7R_FEATURE_AUDIT=1` and `WRAPPER_LOG_LEVEL=info`. If host bit is 0, it deliberately leaves the DXVK 3.1.1 blocker unresolved. No fake feature, Vulkan version override, or texture/shader emulation is included.

The one-file `Wrapper` `.wcp` generated by CI is an **optional diagnostic overlay**, not a complete driver distribution. GameNative's `ContentsManager.applyContent` copies only the declared `usr/lib/libvulkan_wrapper.so` target. Preexisting working wrapper hook libraries, ICD and graphics driver must remain installed. This build is unverified on the device and may be incompatible with the vendor wrapper ABI; keep the existing wrapper profile for immediate rollback.

**If raw feature = 0:** DXVK 3.x needs either an actual Mesa/Turnip implementation of 8-bit SSBO storage (with NIR/IR3 shader lowering and validation for A650) or a correctness-preserving DXVK code path that does not require or emit 8-bit storage SPIR-V. Removing a requirement test alone is not an implementation and cannot be claimed as compatible. Do not waste time spoofing flags.

**If raw feature = 1 but wrapper previous = 0:** verify the new repaired wrapper loads and queries/creates real device; then run the 3.x full missing-feature audit. Further requirements may fail.

### Test one diagnostic launch only

Collect `FF7R-8BIT:` marker and DXVK startup result. Keep LSFG disabled. If no marker, instrumentation is not proven loaded. **No performance comparison or FPS claim for this debug wrapper.**
